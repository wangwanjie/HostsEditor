# macOS 上的 hosts 编辑与方案切换工具

勾选方案，hosts 即刻切换

为开发、测试、预发、线上环境各存一套 hosts。勾选即启用，多个方案组合后经特权 Helper 写回 /etc/hosts，写入后自动刷新 DNS 缓存。

02## features

把 hosts 当成一组可开关的方案来管理

每一项都来自应用的实际功能。

--profiles

多方案管理

创建多套本地 hosts 方案，按需启用、停用、复制或删除；多个启用方案组合后一起写入。

--apply

系统级应用

组合内容写入系统 /etc/hosts，写入后自动刷新 DNS 缓存，修改立即生效。

--remote <url>

远程方案

从 http / https 地址拉取 hosts 保存为方案，可手动刷新，也可每小时、每 6 小时或每天自动刷新。

--backup 30

自动备份

每次写入前备份旧内容，保留最近 30 份，可从「文件」菜单在访达中查看。

--menubar

菜单栏快速切换

状态栏图标列出全部方案，点一下即可启用或关闭，不必打开主窗口。

--highlight

为 hosts 定制的编辑器

注释、IP（含 IPv6）、主机名语法高亮，查找替换、⌘/ 批量注释，支持浅色和深色外观。

--import / --export

导入与导出

把本地 hosts 文件导入为方案，或把当前内容导出为文本文件。

--keep-original

保留原始内容

只改写自己的管理块；写入前重新读取系统 hosts，不覆盖其他工具的修改。

--safe

防误操作

有未保存的修改时窗口关闭按钮显示提示点，退出前二次确认。

03## how-it-works

只改写自己管理的那几段

每个启用的方案写成一个带标记的块，块外的内容原样保留。

/etc/hosts

          

            
系统
当前 /etc/hosts 的完整内容，可直接编辑并保存。

            
默认
剥离 HostsEditor 管理块后的基础内容，只读查看。

            
本地配置
手动维护的方案，可编辑、启用、删除。

            
远程配置
从 URL 拉取的方案，支持刷新。

          

        

        

          
写入流程（示意）

          
    
            
  1. app重新读取 /etc/hosts，保留外部改动
    2. 
            
  2. app组合基础内容与已启用方案
    3. 
            
  3. app备份旧内容（保留最近 30 份）
    4. 
            
  4. xpc→ cn.vanjay.HostsEditorHelper
    5. 
            
  5. rootHelper 写入 /etc/hosts
    6. 
            
  6. rootdscacheutil -flushcache
    7. 
            
  7. rootkillall -HUP mDNSResponder
    8. 
            
  8. app回读校验写入结果
    9. 
            
  9. done已生效
    10. 
          

          
    
            
  • 主应用负责界面、方案管理、状态栏和远程拉取，本身不以 root 运行。
    • 
            
  • Helper 通过 SMAppService 注册为后台守护进程，主应用经 XPC 与它通信。
    • 
            
  • 首次安装或重新注册 Helper 时需要系统授权。

06## getting-started

        
首次使用与常见问题

      

      

        
    
          
  1. 下载与芯片匹配的 DMG，把 HostsEditor 拖进「应用程序」后打开。
    2. 
          
  2. 首次读取或写入系统 hosts 时，应用会注册特权 Helper。
    3. 
          
  3. 系统要求授权时，输入管理员密码。
    4. 
          
  4. 若提示「需要允许后台程序」，前往「系统设置 › 通用 › 登录项与扩展程序」允许 HostsEditor 的后台程序，然后重新打开应用。
    5. 
        

        

          

            出现 “couldn’t communicate with a helper application”
            
通常是系统里残留了旧版本的后台任务记录。先退出 HostsEditor，再在终端清理旧记录：

            

              
sudo launchctl bootout system/cn.vanjay.HostsEditor.Helper 2>/dev/null || true
sudo launchctl bootout system/cn.vanjay.HostsEditorHelper 2>/dev/null || true

              
            

            
确认 /Applications 与 ~/Applications 里只有一份 HostsEditor.app，重新打开应用，点一次「启用或修复后台帮助程序」，再触发一次系统 hosts 的读取或写入。

          

          

            提示「需要允许后台程序」
            
前往「系统设置 › 通用 › 登录项与扩展程序」，允许 HostsEditor 的后台程序，然后重新启动应用。

          

          

            不确定自己的 Mac 是哪种芯片
            
打开「苹果菜单 › 关于本机」，看「芯片」或「处理器」一栏：显示 Apple M 系列选 Apple 芯片版，显示 Intel 选 Intel 版。
